# Кино-тренды Shorts

Сервис отвечает на вопрос: **какие фильмы и сериалы режут на YouTube Shorts для русскоязычной аудитории,
насколько это заходит и какие форматы работают**. Данные нужны конвейеру нарезок (auto-shorts), чтобы выбирать материал.

Интерфейс: `http://127.0.0.1:18320` локально. Для доступа снаружи проксируйте порт своим nginx по секретному пути и запишите этот путь в `var/public-path.txt` (сервис подставляет его в абсолютные ссылки).
Разделы: **Сегодня** (рабочий экран дня: кино из календаря и подборка видео под перезалив, ссылки для нарезчика и заливщика, отметки «сделано» и «залито», `GET /api/today`) · **Видео** (популярное СНГ под перезалив) · **Кино** (Что резать · Обзор · Фильмы и сериалы · Интересы · Каналы · Ролики; фильтры периода и языка действуют только здесь) · **Сбор** (прогон, нейросеть, Telegram, хранилище, видео, источники, настройки).

## Откуда данные
| Источник | Что даёт | Ограничение |
|---|---|---|
| Страница хэштега, вкладка Shorts (`youtube.com/hashtag/<тег>/shorts`) | id, заголовок, округлённые просмотры, миниатюра; до 400 роликов за запрос | нет дат и длительности |
| Вкладка Shorts канала | то же по каналам в слежении, плюс подписчики | нет дат |
| RSS канала (`feeds/videos.xml`) | точные даты, просмотры и лайки последних 15 роликов | только 15 |
| HTML страницы ролика (`youtube.com/shorts/<id>`) | название, описание, длительность, дата, категория, ключевые слова, канал, точные просмотры, доступность в RU | лайков и комментариев нет; ~0,4 с на ролик при 4 потоках |
| YouTube Data API v3 (ключ в настройках) | всё выше плюс лайки и комментарии, 50 роликов за 1 единицу квоты; чарты популярного и поиск Creative Commons для раздела «Видео» | нужен ключ Google Cloud |
| Wikidata | словарь: 133 тыс. фильмов, сериалов, мультфильмов, аниме и телешоу с ID Кинопоиска, годы, жанры, страны, псевдонимы | сборка около часа, возобновляемая |

Страница плеера (`/watch`) с датацентровых IP режется проверкой «вы не бот», поэтому yt-dlp для деталей не используется: только страницы списков и HTML шортса.

## Как опознаётся произведение
Сила улик по убыванию: подпись «Название: …» / «Фильм — …» / «из фильма «…»» (0,95) → кавычки (0,85) → хэштег-название (0,8) → сегмент заголовка между `|` или после тире (0,7) → название словаря в тексте с заглавной буквы (0,5–0,72) → привязка канала, заданная оператором (0,75). Год в тексте сверяется со словарём. В статистику попадают ролики с уверенностью не ниже порога (по умолчанию 0,6, меняется в фильтрах). Ручная разметка в разделе «Ролики» учит словарь: написание сохраняется как псевдоним.

## Нейросеть (OpenRouter, OpenAI-совместимый API)
- **Опознание по кадру.** Для роликов, которые словарь не взял, модель получает миниатюру, заголовок, описание, хэштеги, канал и то, что канал резал раньше, и отвечает JSON с названием, годом, типом и уверенностью. Ответ сопоставляется со словарём; незнакомые произведения создаются с пометкой `source='neuro'`. Бейк-офф на 12 роликах с известным ответом: `google/gemini-2.5-flash-lite` 10/12 за 0,26 $ на 1000 роликов (выбрана), `google/gemini-2.5-flash` 10/12 за 0,97 $, `qwen3-vl-30b` 6/12. Лимиты: `neuro_per_run`, `neuro_min_views`, `neuro_daily_usd`.
- **Сцены и хуки.** По заголовкам и просмотрам роликов произведения модель группирует их по сценам (что именно резать), предлагает 5 заголовков-хуков и советы. Кнопка на странице произведения, результат кэшируется в `title_insights`.

## Исходники и бриф для конвейера
Главный результат работы сервиса: не чужие нарезки, а исходник под нож и объяснение. Для каждого произведения в календаре:
- **Исходник**: полный фильм или серии на YouTube, найденные поиском (yt-dlp, страницы поиска доступны с сервера) и проверенные моделью:
  отбраковываются трейлеры, пересказы, реакции, чужие фильмы с похожим названием; определяются серия, сезон, язык озвучки, официальный ли канал.
  Таблица `title_sources`, `GET/POST /api/films/{id}/sources`. Ссылка уходит в конвейер; скачивание с этого сервера невозможно (плеер YouTube заблокирован).
- **Почему**: человеческое объяснение от модели по статистике и лучшим чужим роликам (`title_explain`, `GET/POST /api/films/{id}/explain`).
- **Сцены** с репликами для поиска по субтитрам и ориентиром «где в фильме», хуки, план (длительность, время, хэштеги).
- **Бриф** `GET /api/brief/{id}` и `GET /api/brief/today`: поле `deliverable` содержит ровно то, что нужно конвейеру: источник, сцены с репликами и референсами, хуки, длительность, хэштеги, время. Чужие шортсы лежат в `references` как доказательство.
Всё это считается автоматически после каждого прогона для произведений календаря на неделю вперёд.

## Прямая ссылка для нарезчика и сервер-хранилище
В каждой карточке календаря первый блок «Ссылка для нарезчика» с кнопкой «скопировать»: прямой mp4 из хранилища.
Хранилище — отдельный VPS (настройки `storage_*` в разделе «Сбор»): туда по SSH уходит команда yt-dlp, файл раздаёт nginx
(`storage_url/<id>.mp4`). С отдельного IP качаются и YouTube, и Rutube (с основного сервера YouTube не качается, обход бот-защиты не делаем).
720p экономным битрейтом, файлы на сегодня и завтра готовятся сами в конце прогона и кнопкой «подготовить mp4 на сегодня»,
хранятся `storage_ttl_hours` (72 ч), потолок `storage_max_gb` (20 ГБ). На основном сервере видео не хранятся.
Подготовка хранилища: Ubuntu, `apt install ffmpeg nginx`, yt-dlp standalone в /usr/local/bin, Node из tarball в /usr/local,
каталог /srv/files (владелец www-data), nginx location /files/ с alias на него, ключ ~/.ssh/kt_storage.pub в authorized_keys root.

## Для нарезчика (auto-shorts и любой другой)
Нарезчик принимает ссылку YouTube или прямую ссылку на файл. Поэтому в брифе блок `cutter`:
`source_url` (YouTube в приоритете: нарезчик качает сам), `direct_file_url` (для Rutube сервер скачивает 720p в `var/files`
по кнопке «подготовить файл», раздаёт по `files/<id>.mp4`, хранит 48 часов, не больше 8 ГБ, при менее 5 ГБ свободного места отказывает),
`hint` (текст для поля «Что искать»: сцены, что резать, реплики, подача), `clip_min_s`/`clip_max_s` (из лучшей корзины длительности, не больше 59 с, если права не свободны), `rights_ok` и `rights_level`.

## Видео под перезалив (популярное в СНГ)
Второй контур сервиса (`kinotrends/popular.py`, раздел «Видео»): не кино, а популярные ролики, которые можно перезалить со своим баннером.
- **Источник.** YouTube Data API v3 (`youtube_api_key`): чарт «самое популярное» по странам `pop_regions` (1 единица квоты за страницу из 50),
  чарты России по категориям `pop_categories`, раз в `pop_cc_hours` поиск роликов с лицензией Creative Commons по запросам `pop_cc_queries`
  (100 единиц за запрос). Замеры просмотров между прогонами дают прирост в день; подписчики каналов через channels.list.
- **Разбор.** Модель по тексту: тема, формат, хук, кто смотрит, спонсор, уже ли это перезалив, кадры ли это из фильма, пригодность под чужой
  баннер и **совпадение с нашей аудиторией** (профиль в `pop_audience`, по умолчанию аудитория VPN: YouTube без замедления, Discord, Instagram,
  Roblox, зарубежные игры и сервисы). Кадры: на хранилище yt-dlp отдаёт прямой URL потока, ffmpeg вынимает 6 кадров по времени без скачивания
  всего видео и собирает лист 3×2; модель со зрением ищет водяные знаки, логотипы, плашки, призывы подписаться, рекламу, рамки и называет
  свободные зоны под баннер. Листы кадров лежат в `var/frames`, отдаются по `api/videos/{id}/frames.jpg`.
- **Оценка.** Балл 0–100 и уровень `clean` (от 70, кадры проверены, нет логотипов и заявок) / `check` (от 45) / `no` / `unknown`. Вниз: заявка
  партнёра YouTube (Content ID), канал правообладателя из списка `rights.HOLDERS`, музыка, новости, водяной знак, чужая реклама, спонсор, не наш язык.
  Вверх: Creative Commons, совпадение с аудиторией (до ±20), пригодность под баннер, прирост просмотров, категории игр и техники, чистые кадры.
  Решение оператора сильнее автомата.
- **Подборка.** Чистые с баллом от `pop_pick_min_score` попадают в подборку сами (`pop_auto_pick`); руками можно взять или убрать любой.
  `GET /api/videos/picks` отдаёт заливщику: ссылку, прямой mp4 из хранилища (`POST /api/videos/{id}/file`, `POST /api/videos/picks/prepare-files`),
  лист кадров, свободные зоны, совет по баннеру, совпадение с аудиторией. Остальное: `GET /api/videos` (фильтры level, region, category, dur, lang,
  q, sort, pick, fit), `GET /api/videos/{id}`, `POST /api/videos/{id}/analyze|pick|level`, `POST /api/videos/refresh`, `GET /api/videos/overview`.
- Лимиты за прогон: `pop_llm_max` разборов текста, `pop_frames_max` проверок кадров (15–30 с каждая на хранилище). Квота Data API считается
  в `meta` по дням и видна в обзоре.

## Авторские права
Каждое произведение календаря проходит проверку (`kinotrends/rights.py`, фаза «авторские права» перед сборкой календаря):
- **Сносы.** Опознанные чужие нарезки из календаря и топа перечитываются (`rights_recheck_max` страниц за прогон). Если YouTube удалил ролик
  по жалобе правообладателя, страница называет заявителя; закрытие канала тоже считается. Доля сносов идёт в риск, заявители видны в обзоре.
- **Правообладатель.** Модель называет студию или платформу и её привычки (блокирует и страйкует / заявляет права через Content ID / терпит),
  общественное достояние, официальную бесплатную выкладку, музыкальный риск (`rights_llm_max` произведений за прогон, ответ живёт 30 дней).
  Для известных правообладателей (Disney, Warner, Universal, японские студии, Первый канал, ВГТРК, Газпром-Медиа, Кинопоиск, Мосфильм и др.)
  действует свой список, он сильнее ответа модели.
- **Исходник.** Официальный канал снижает риск; мёртвый исходник повышает и снимает отметку «проверено», чтобы поиск повторился.
- **Наш опыт.** `POST /api/rights/events` {title_id, kind: claim|block|strike|ok, note} от нарезчика или кнопка на странице произведения.
  Страйк и блок сразу выводят произведение из календаря, чистые публикации снижают риск. Ручное решение оператора сильнее всего.

Итог: уровень `ok` / `caution` / `block` / `unknown`, риск 0–100 (от 40 с оговорками, от 65 не проходит), причины словами.
Политика `rights_policy`: `strict` пускает в календарь только `ok`, `balanced` (по умолчанию) `ok`, `caution` и непроверенные, `off` только помечает.
Правило длины: шортс дольше 60 с с любой заявкой Content ID блокируется, поэтому в брифе `cutter.clip_max_s ≤ 59`, кроме свободных произведений.
Эндпоинты: `GET /api/films/{id}/rights`, `POST /api/films/{id}/rights/refresh`, `POST /api/films/{id}/rights/manual`, `GET /api/rights/overview`.

## Интерес аудитории и охват
- Википедия (Pageviews API, статья из Wikidata) и Google Trends по России (pytrends): среднее за 7 дней против 30, рост ≥ 1,5 добавляет балл возможности. Обновляется после прогона для топ-120 и календаря; на странице произведения графики и «обновить сейчас».
- Охват: 400 роликов с хэштега, 120 со вкладки канала, 2 500 страниц деталей за прогон, поиск шортсов по названиям из топа и календаря («<название> #shorts»), хэштеги самих произведений (#рикиморти) из улик распознавания, автоканалы и автохэштеги. С ключом Data API ещё и верхние комментарии неопознанных роликов (там часто пишут название).
- Интерфейс по умолчанию показывает ролики за 90 дней по дате публикации; «всё» показывает всю базу.

## Что резать и календарь
- `/api/recommend` — произведения с объяснением «почему»: спрос (просмотров в день, прирост по замерам), предложение (число каналов), свежесть, план (длительность, хук, время публикации по МСК, хэштеги, референсы).
- `/api/schedule` — календарь нарезки на N дней вперёд: чередует типы, не повторяет произведение раньше cooldown, ручные правки и отметки «сделано/пропустить» сохраняет; достраивается после каждого прогона.
- `/api/brief/{title_id}` и `/api/brief/today` — бриф для конвейера auto-shorts: произведение, причины, сцены, хуки, план, референсы, расписание.
- Telegram: ежедневный дайджест в `digest_hour` по МСК (календарь на сегодня и завтра плюс топ-8) и тревоги после прогона, когда произведение входит в топ по скорости. Нужны `telegram_bot_token` и `telegram_chat_id` в настройках.
- Постеры: статика Кинопоиска по kp_id, запасной путь Wikidata P18; кэш в `var/posters`.
- Автодобор хэштегов: теги, под которыми много опознанных киношортсов, добавляются в источники (до `auto_hashtags_max`).
- Сезоны и серии разбираются из заголовков («3 сезон 7 серия», s02e05) и показываются в карточке сериала.

## Метрики
- **Балл** произведения (0–100): 45 % ранг по сумме просмотров в день (просмотры ÷ возраст ролика), 25 % ранг по числу роликов за 7 дней, 20 % по медиане просмотров, 10 % по числу каналов.
- **Мало конкурентов**: медиана выше 75-го перцентиля и не больше трёх каналов.
- **Прирост за 7 дней**: разность точных замеров (страница, RSS, API) между прогонами; появляется после второго прогона.
- Интересы: жанры, тип, страна, эпоха, длительность, приёмы заголовка, хэштеги, язык, день недели и час публикации (МСК); сравнение по медиане, числу роликов, сумме, P75.

## Запуск
```
.venv/bin/python -m kinotrends serve            # или scripts/service.sh start|stop|restart|status|logs
.venv/bin/python -m kinotrends collect          # один прогон из консоли
.venv/bin/python -m kinotrends import-dict      # импорт словаря из var/dict/entities.jsonl
scripts/dict-fetch.sh 4                         # сборка словаря Wikidata в фоне (4 потока)
.venv/bin/python -m pytest -q tests
```
Сбор по расписанию встроен в сервис: `schedule_hours` в настройках (по умолчанию 6 ч, 0 = выключено). Словарь подхватывается автоматически раз в 10 минут, пока идёт сборка.

## Устройство
`kinotrends/` — `db.py` схема SQLite (WAL), `collector.py` прогон, `recognize.py` распознаватель, `stats.py` статистика, `api.py` FastAPI, `yt/` источники (flat, page, rss, dataapi), `dictionary/` Wikidata. `web/` — интерфейс без зависимостей и внешних ресурсов. `var/` — база `kinotrends.sqlite`, словарь, миниатюры, журналы. `tests/` — pytest.
